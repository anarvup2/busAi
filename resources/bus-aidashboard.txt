## How the counting actually works

The camera counts when a detected person crosses the configured **detection line** inside the configured **detection area**.

In your debug view:

```txt
Blue box = maximum detection range
Red box = actual selected detection area
Green line = detection line
Green arrow = entry direction
Yellow circles / labels = detected people + height
```

The manual says the detection area should be drawn only over the ground passage area, and every entry/exit should pass through the middle detection line. The arrow direction decides what is counted as “In.” 

So the counting logic is basically:

```txt
Person detected inside red area
↓
Person crosses green line
↓
Direction matches arrow = In
Opposite direction = Out
Side movement = Passby / Turnback depending on movement
```

### 3. Child mode

Enable child mode only if the client really wants adult/child split.


Then:

```txt
height < child height and height > filter height = child
height >= child height = adult
```

But do not oversell this. This is not age detection. It is height-based classification. A short adult may be counted as child, and a tall child may be counted as adult.

Keep the red box only on the walking area near the bus door.

Do **not** include:

```txt

driver area
walls
stairs if irrelevant
objects near the door
```

The manual says the detection range cannot exceed the ground area and should be drawn according to the actual passage area.

Place the line where every passenger must cross.

For a bus, this should usually be near the entry/exit door passage, not too close to the edge.

Direction matters:

```txt
Arrow toward inside bus = boarding = In
Arrow toward outside bus = exiting = Out
```

If the dashboard shows reversed numbers, flip detection direction.

## How data comes to your software

The camera sends HTTP POST JSON to your server.

There are two main endpoints:

```txt
POST /api/camera/heartBeat
POST /api/camera/dataUpload
```

The API document says reporting uses HTTP protocol with POST + JSON. It supports heartbeat and data upload. Heartbeat is every 1 minute, and data upload frequency can be 0, 1, 5, or 60 minutes. 

### Heartbeat payload

The camera sends:

```json
{
  "sn": "2010010000000000",
  "time": 1641434640
}
```

Your backend should return:

```json
{
  "code": 0,
  "msg": "success",
  "data": {
    "sn": "2010010000000000",
    "time": 1641434640,
    "uploadInterval": 5,
    "dataMode": "Add"
  }
}
```

The response can also include start/end time, upload interval, data mode, timezone, and server time. 

### Data upload payload

The camera sends counts like:

```json
{
  "sn": "2100002507152593",
  "startTime": 1719120000,
  "endTime": 1719120300,
  "time": 1719120300,
  "in": 4,
  "out": 2,
  "passby": 0,
  "turnback": 1,
  "avgStayTime": 1000,
  "inAdult": 3,
  "outAdult": 2,
  "inChild": 1,
  "outChild": 0,
  "total": 6
}
```

The API supports fields like `in`, `out`, `passby`, `turnback`, `avgStayTime`, `inAdult`, `outAdult`, `inChild`, `outChild`, and other adult/child/passby fields. 

It may also send `eventList`:

```json
{
  "eventList": [
    {
      "id": 5368,
      "timestamp": 161231947237000000,
      "eventType": 0,
      "height": 180,
      "stayTime": 1000
    }
  ]
}
```

That is the more detailed event-level data. Useful, but don’t depend on it until you confirm the exact payload from your physical device.

## How to calculate bus-level analytics

For each bus:

```txt
front_in = sum(in_count where door_position = FRONT)
rear_in = sum(in_count where door_position = REAR)

front_out = sum(out_count where door_position = FRONT)
rear_out = sum(out_count where door_position = REAR)

bus_total_in = front_in + rear_in
bus_total_out = front_out + rear_out
```

Estimated occupancy:

```txt
occupancy = total_in - total_out
```

But be careful. Occupancy can drift if the camera misses people. Reset occupancy at trip start/end or depot.
