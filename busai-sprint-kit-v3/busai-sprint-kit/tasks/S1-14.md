## Context

The vendor gave a browser-only SDK (docs/vendor/warner-h5sdk.md): it needs window, document, localStorage and WebAssembly, reaches cameras through the dvr163.com P2P relay, and returns raw frames via ConnectApi.onrecvframeex. Run it in headless Chromium and expose a small, allow-listed API to our Python services. Do this first in Sprint 1: S1-05 and S1-08 depend on it.

## Deliver

- services/warner_bridge/ (Node 20 + Playwright): loads the SDK from vendor/warner_h5sdk/ (checksum-verified) in a headless page; wires ConnectApi callbacks directly (no canvas rendering needed)
- Session pool: one P2P session per camera; preconnect (connectType 0) → login → OpenStream(streamid 0) on window open → CloseStream on window close → disconnect after an idle timeout; reconnect with backoff; Warner error codes mapped to typed errors
- Frame path: onrecvframeex → drop frametype 0 (audio) → send {kind, codec, width, height, fps, ts, bytes} over a Unix socket (length-prefixed) to services/camera_adapters/warner.py
- Playback path: SreachRecord + StartPlayBack + onrecvrecframe, serialised per device
- MQTT allow-list: getDeviceModal, gets of time/health/posture properties, R.Sync.Stat.TF and R.Sync.Stat.NetWork only; set System.Time.TimeUtc only if DECISIONS.md approves; everything else refused in code; User.List never requested
- Credentials from env only; refuses device user admin with an empty password; never uses the token or app key embedded in the SDK; never uses the demo's password-derivation logic
- tools/commission_warner.py: dry-run by default; prints current posture and planned changes; with --apply (run by a person, H-15) sets a unique device password from the vault and turns alarm push, on-camera boxes and audio input off, continuous sub-stream SD recording on
- docker image for the bridge; health endpoint; memory and session metrics
